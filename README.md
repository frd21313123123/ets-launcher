# ETS & ATS Launcher — установщик на Rust

<img src="assets/branding/icon.png" width="80" height="80" alt="Логотип Truck Launcher">

[![Windows build](https://github.com/frd21313123123/ets-launcher/actions/workflows/windows.yml/badge.svg)](https://github.com/frd21313123123/ets-launcher/actions/workflows/windows.yml)

Нативное приложение Windows для Euro Truck Simulator 2 и American Truck Simulator: `egui/eframe`, встроенный BitTorrent-клиент `librqbit`, HTTPS через `reqwest` и встроенный распаковщик 7-Zip. Сборка из GitHub Releases запускается одним `.exe`, без установки Rust, Visual C++ Redistributable, торрент-клиента или архиватора.

## Запуск

Скачайте **[ets-launcher.exe из последнего релиза](https://github.com/frd21313123123/ets-launcher/releases)** и запустите его. Файлы и лицензии 7-Zip встроены в приложение и автоматически подготавливаются в локальном кэше пользователя при первой распаковке. Папка `tools/7zip` рядом с `.exe` не требуется. При повреждении или удалении файлов кэша приложение восстанавливает их из встроенной копии.

Откройте `launch.cmd` либо `dist/ets-launcher.exe`, выберите игру на боковой панели (**Euro Truck Sim 2** или **American Truck Sim**), откройте раздел **DLC карт**, закройте выбранную игру и нажмите **Установить DLC**. Если на странице есть beta-пакет, выберите ветку **Обычная** или **Beta**, соответствующую установленной версии Steam. Доступные ветки определяются со страницы для обеих игр.

На боковой панели переключаются разделы (**DLC карт**, **Сборки Quper**, **Настройки**) и тема оформления — **Чёрная** или **Светлая**; выбор темы сохраняется в настройках. Шрифты интерфейса (Manrope, JetBrains Mono, лицензия OFL) встроены в приложение, см. `assets/fonts`.

## Готовые сборки Quper

Раздел **Сборки Quper** получает готовые сборки ETS2 и ATS с [qupersimulator.ru](https://qupersimulator.ru/): обложку, название, версию игры, версию сборки, дату, страницу и ссылку на таблицу файлов. Есть поиск, выбор игры и версии, в том числе архивных выпусков. Сборки с пометкой Boosty не показываются. Каталог обновляется при запуске, каждые 30 минут и по кнопке; данные сайта читаются без выполнения его JavaScript. Отдельный JSON-каталог с GitHub для этого раздела больше не нужен.

1. Выберите сборку и папку её хранения. Лаунчер читает публичную таблицу именно выбранного листа и авторский порядок модов с сайта Quper.
2. Нажмите **Скачать сборку**. Очередь получает публичные файлы, сохраняет авторские имена, проверяет архивы и распаковывает сборные архивы. Один архив может содержать несколько модов. Уже полученные пакеты сохраняются для продолжения после остановки.
3. Если хостинг требует браузер, открывается встроенная очередь WebView2. На Sharemods и ModsFire лаунчер нажимает обычные бесплатные кнопки сайта и ждёт его таймер. Проверки сайта и вход выполняются пользователем. Завершённые браузерные загрузки автоматически импортируются; после получения нужных частей очередь переходит к следующему источнику. **Следующий источник** позволяет оставить проблемную страницу и продолжить остальные файлы. Ручные архивы добавляются через **Импорт файлов**.
4. Когда получены все моды из порядка Quper, создаётся отдельное окружение и чистый профиль с этим порядком. **Играть** запускает выбранную игру через Steam, если она найдена в его библиотеке, с отдельным `-homedir`. Профили ETS2 и ATS разделены; повторная проверка готовой сборки сохраняет карьеру. Нужны указанная версия игры и DLC карт.

**Boosty полностью исключён из запросов и переходов автоматической очереди.** Даже в бесплатной сборке отдельная строка таблицы может вести только на Boosty. Такая строка помечается как требующая импорта; недостающий обязательный мод не пропускается. Лаунчер показывает точное количество готовых модов и не разрешает запуск неполной сборки. Недоступный файл, регистрация у автора или изменившийся протокол хостинга могут потребовать действий на его сайте либо импорта уже имеющегося файла.

Каталог и списки файлов кэшируются отдельно от прежнего менеджера карт. При сетевой ошибке сохранённые данные остаются доступны. Прежние библиотеки и сборки на диске сохраняются; активный экран больше не смешивает отдельные карты и не получает правила стыковок из старого каталога.

Встроенный браузер требует Microsoft WebView2 Runtime. MSVC-сборка содержит статический загрузчик; локальная GNU-сборка комплектуется `WebView2Loader.dll` и DLL своего toolchain.

Диагностика:

```text
ets-launcher.exe --quper-catalog <report.json>
ets-launcher.exe --quper-plan <combo-id> <report.json>
ets-launcher.exe --quper-download <combo-id> <library-folder> <report.json>
ets-launcher.exe --quper-file <public-file-url> <download-folder> <report.json>
```

`--quper-catalog` и `--quper-plan` скачивают только метаданные; `--quper-download` получает настоящие файлы сборки, которые могут занимать десятки гигабайт. Отчёт различает готовое окружение и недостающие файлы. Для изолированных проверок задайте абсолютную папку `ETS_LAUNCHER_CONFIG_DIR`. Тесты Quper находятся в `tests/quper.rs`; подробности проверки — в [docs/quper-verification.md](docs/quper-verification.md).

## Актуальные данные DLC без пересборки

При запуске и каждые **5 минут** приложение читает страницы PlayGround в фоне и обновляет версии, имена архивов, размеры, ID файлов и доступность обычной/beta-ветки. В окне показаны текущая версия на источнике, файл и время проверки. Есть кнопка **Обновить данные**. Во время установки очередное фоновое обновление откладывается до её завершения.

Версии берутся из подписей файлов и их имён. При нескольких пронумерованных версиях в одной ветке выбирается самая новая; при неоднозначности установка не начинается. Встроенного устаревающего торрент-файла в приложении нет: фиксированный `.torrent` в `assets` используется только тестами.

Последние успешно полученные данные сохраняются в `catalog.json` рядом с настройками в AppData. Если сайт недоступен, они помечаются как сохранённые. **Перед скачиванием источник всегда проверяется заново**; кэш не подменяет новый торрент старым. Архивы автоматически не скачиваются и не устанавливаются при фоновом обновлении данных.

При обновлении файлов в этих публикациях новую версию лаунчера собирать не нужно. Если автор создаст новую публикацию, её ссылку можно заменить в **Настройки → Страница источника PlayGround → Применить**, отдельно для каждой игры. Перенаправления со старого адреса обрабатываются автоматически. Изменение самой HTML-разметки/API сайта может потребовать обновления парсера.

Приложение автоматически:

1. Находит выбранную игру по реестру и библиотекам Steam: ETS2 — приложение `227300` и `eurotrucks2.exe`, ATS — `270880` и `amtrucks.exe`. Проверяет, что выбранная игра закрыта и другая копия лаунчера не устанавливает файлы в эту папку.
2. Заново читает настроенную страницу PlayGround для [ETS2](https://www.playground.ru/euro_truck_simulator_2/cheat/ets_2_dlc_unlocker_razblokirovschik_dopolnenij_1_61_1_9s_steam_nicholaspooh-1660372) или [ATS](https://www.playground.ru/american_truck_simulator/cheat/ats_dlc_unlocker_razblokirovschik_dopolnenij_1_61_3_18s_1_62_0_4s_beta_steam_nicholaspooh-1660567), получает актуальный `.torrent` для выбранной ветки через API сайта и сохраняет его. Ожидание, назначенное сайтом, отображается в окне (обычно 60 секунд). Отсутствие нужной ветки вызывает ошибку вместо подмены другой.
3. Скачивает архив встроенным торрент-клиентом, проверяя части по хешам. При повторном запуске проверяет имеющиеся части и продолжает загрузку. По завершении торрент-сессия останавливается.
4. Проверяет пути и структуру архива, доступное место, распаковывает его во временную папку и проверяет CRC. Пароли, ссылки, пути за пределы папки распаковки и неоднозначные имена не поддерживаются.
5. Находит папку с `dlc_*.scs`, включая архивы с внешней папкой. Устанавливает карты в корень выбранной игры и файлы из `bin/win_x64` / `bin/win_x86` в соответствующие подпапки. Проверяет соответствие имени архива выбранной игре, сохраняет исполняемый файл игры. Документация остаётся в архиве. Неизвестная структура вызывает понятную ошибку до замены файлов.
6. Сохраняет оригиналы заменяемых файлов в `.ets-launcher/backups/<номер>/original` внутри игры, затем заменяет файлы. При отмене или ошибке восстанавливает оригиналы и удаляет добавленные файлы. Журнал позволяет восстановить незавершённую установку при следующем нажатии **Установить DLC** после аварийного выхода.

Кнопка **Остановить** отменяет текущую операцию. При обычном закрытии окна приложение сначала завершает остановку и откат, затем закрывается. Готовый архив остаётся в кэше.

В свёрнутых **Настройках** можно выбрать папку текущей игры вручную, повторить поиск и изменить корень кэша загрузок. Папки ETS2 и ATS запоминаются отдельно. Существующий кэш ETS2 остаётся в `Загрузки/ETS Launcher`, ATS использует подпапку `ATS`. Старые настройки ETS2 загружаются без повторного выбора папки. Настройки хранятся в AppData. Резервные копии сохраняются в папке соответствующей игры после успешной установки.

Для VPN с обходом по приложениям добавьте именно `dist/ets-launcher.exe` в исключения. Настройки VPN приложение не меняет. Доступность загрузки зависит от сайта и наличия пиров. Совместимость содержимого DLC с версией игры определяется выбранным источником.

## Сборка

Проект проверен с Rust 1.99.1 (Windows GNU). Локальный toolchain находится в `.tools`, системный PATH не меняется.

```powershell
# Если локальный Rust ещё не установлен
.\scripts\bootstrap.ps1

.\scripts\cargo.ps1 test --locked
.\scripts\cargo.ps1 build --release --locked
.\scripts\package.ps1
```

`package.ps1` собирает `dist`. Официальные `7z.exe`, `7z.dll` и лицензии входят в сам лаунчер; источник и контрольные суммы приведены в `assets/7zip/ORIGIN.md`. Автосборка MSVC статически включает C runtime и выдаёт самостоятельный `.exe`. Локальная отладочная сборка GNU дополнительно использует две DLL своего toolchain, которые скрипт копирует в `dist`.

Логотип встроен в `.exe` как иконка Windows и используется в окне приложения. Отдельная копия `ets-launcher.ico` входит в `dist` для ярлыков. Исходник и промпт находятся в `assets/branding`; размеры иконки пересоздаются скриптом `scripts/make-icons.ps1`.

Для системного GNU нужны инструменты MinGW/LLVM, для MSVC — соответствующие Build Tools. Обёртка `scripts/cargo.ps1` настраивает локальные LLVM dlltool и LLD.

## Автосборка GitHub Actions

Workflow **Windows build** запускается при push, pull request и вручную через **Actions → Windows build → Run workflow**. Он проверяет форматирование, Clippy и тесты, собирает Windows x64 на Rust 1.99.1 (MSVC), затем копирует **только `.exe`** в отдельную папку с кириллицей и пробелами и проверяет установку на временных папках ETS2 и ATS с пустым кэшем распаковщика. Дополнительно проверяются импорты PE: допускаются системные DLL Windows, внешние библиотеки VC++/GNU и архиватора приводят к ошибке сборки.

Готовое приложение: **[Releases](https://github.com/frd21313123123/ets-launcher/releases) → самая новая сборка → ets-launcher.exe**. Для запуска достаточно этого одного файла. Рядом опубликован `ets-launcher.exe.sha256` для проверки целостности.

Каждый push в `main` и ручной запуск для `main` публикует проверенную сборку как предварительный релиз `build-<commit>`. Повторный запуск того же коммита обновляет только его файлы. Ветки и pull request проходят проверки без публикации. Выдача `.exe` через Releases не использует квоту Actions Artifacts. CI работает с тестовыми архивами и не скачивает настоящий пакет DLC.

Для аналогичной сборки из Windows с настроенным MSVC Rust:

```powershell
$env:RUSTFLAGS = '-C target-feature=+crt-static'
.\scripts\package.ps1 -Target x86_64-pc-windows-msvc
.\scripts\smoke-test.ps1 -Standalone
.\scripts\verify-standalone.ps1 -Executable dist/ets-launcher.exe
```

## Проверки

Автоматические тесты работают с временной папкой игры и маленькими архивами:

- HTTP: совпадение байтов, сохранность существующих файлов, обрыв ответа, HTTP 404 и отмена.
- PlayGround: основной файл, актуальные идентификаторы, серверное ожидание и `lock_hash`, проверка `.torrent`.
- BitTorrent: реальная локальная передача, проверка частей, отмена без пиров; цепочка **торрент → архив → распаковка → установка в тестовую ETS2**.
- Установка: RAR5, внешняя папка и кириллица, резервные копии, сохранность исполняемого файла игры, откат при отмене/ошибке, восстановление после прерванного процесса, блокировка параллельной установки, опасные пути и повреждённый архив.
- Самостоятельный EXE: встроенный распаковщик и лицензии, параллельная подготовка кэша, восстановление повреждённых файлов, запуск из отдельной папки с пустым кэшем. Проверка использует временную `ETS_LAUNCHER_TOOL_CACHE`, не затрагивая обычный кэш приложения.
- Поиск игры: дополнительные библиотеки Steam, старый VDF, кириллица, недоступные диски и устаревшие записи.
- ATS: отдельный манифест Steam, защита от выбора папки ETS2, сохранение обеих папок, выбор stable/beta и соответствующие запросы API, установка с сохранением `amtrucks.exe`.
- Динамический каталог: изменение версий и ID без изменения кода, числовое сравнение версий, beta-подпись без beta в имени, появление/исчезновение веток, перенаправление на новый адрес, раздельный кэш и редактирование ссылок.

Полный пакет DLC и запуск настоящей игры в автоматические тесты не входят.

Диагностика получения только `.torrent` из готового приложения с учётом исключения VPN:

```powershell
Start-Process .\dist\ets-launcher.exe -ArgumentList '--fetch-torrent','artifacts/site-smoke' -WindowStyle Hidden -Wait
Get-Content .\artifacts\site-smoke\result.txt
```

Диагностика установки локального архива требует явного пути к тестовой игре и файлу отчёта:

```text
ets-launcher.exe --install-archive <archive> <game-directory> <report-file>
```

Необязательный последний аргумент выбирает игру (`ets2` по умолчанию):

```text
ets-launcher.exe --install-archive <archive> <game-directory> <report-file> ats
ets-launcher.exe --detect-game <report-file> ats
ets-launcher.exe --fetch-torrent <output-directory> ats stable
ets-launcher.exe --fetch-torrent <output-directory> ats beta
ets-launcher.exe --catalog <json-report-file> ats
ets-launcher.exe --catalog <json-report-file> ets2
```
