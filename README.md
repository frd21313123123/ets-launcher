# ETS & ATS Launcher — установщик на Rust

[![Windows build](https://github.com/frd21313123123/ets-launcher/actions/workflows/windows.yml/badge.svg)](https://github.com/frd21313123123/ets-launcher/actions/workflows/windows.yml)

Нативное приложение Windows для Euro Truck Simulator 2 и American Truck Simulator: `egui/eframe`, встроенный BitTorrent-клиент `librqbit`, HTTPS через `reqwest` и комплектный распаковщик 7-Zip. Отдельный торрент-клиент или архиватор не нужен.

## Запуск

Откройте `launch.cmd` либо `dist/ets-launcher.exe`, выберите **Euro Truck Simulator 2** или **American Truck Simulator**, закройте выбранную игру и нажмите **Установить DLC**. Если на странице есть beta-пакет, выберите ветку **Обычная** или **Beta**, соответствующую установленной версии Steam. Доступные ветки определяются со страницы для обеих игр.

## Актуальные данные без пересборки

При запуске и каждые **5 минут** приложение читает страницы PlayGround в фоне и обновляет версии, имена архивов, размеры, ID файлов и доступность обычной/beta-ветки. В окне показаны текущая версия на источнике, файл и время проверки. Есть кнопка **Обновить данные**. Во время установки очередное фоновое обновление откладывается до её завершения.

Версии берутся из подписей файлов и их имён. При нескольких пронумерованных версиях в одной ветке выбирается самая новая; при неоднозначности установка не начинается. Встроенного устаревающего торрент-файла в приложении нет: фиксированный `.torrent` в `assets` используется только тестами.

Последние успешно полученные данные сохраняются в `catalog.json` рядом с настройками в AppData. Если сайт недоступен, они помечаются как сохранённые. **Перед скачиванием источник всегда проверяется заново**; кэш не подменяет новый торрент старым. Архивы автоматически не скачиваются и не устанавливаются при фоновом обновлении данных.

При обновлении файлов в этих публикациях новую версию лаунчера собирать не нужно. Если автор создаст новую публикацию, её ссылку можно заменить в **Настройки → Страница источника PlayGround → Применить ссылку**, отдельно для каждой игры. Перенаправления со старого адреса обрабатываются автоматически. Изменение самой HTML-разметки/API сайта может потребовать обновления парсера.

Приложение автоматически:

1. Находит выбранную игру по реестру и библиотекам Steam: ETS2 — приложение `227300` и `eurotrucks2.exe`, ATS — `270880` и `amtrucks.exe`. Проверяет, что выбранная игра закрыта и другая копия лаунчера не устанавливает файлы в эту папку.
2. Заново читает настроенную страницу PlayGround для [ETS2](https://www.playground.ru/euro_truck_simulator_2/cheat/ets_2_dlc_unlocker_razblokirovschik_dopolnenij_1_61_1_9s_steam_nicholaspooh-1660372) или [ATS](https://www.playground.ru/american_truck_simulator/cheat/ats_dlc_unlocker_razblokirovschik_dopolnenij_1_61_3_18s_1_62_0_4s_beta_steam_nicholaspooh-1660567), получает актуальный `.torrent` для выбранной ветки через API сайта и сохраняет его. Ожидание, назначенное сайтом, отображается в окне (обычно 60 секунд). Отсутствие нужной ветки вызывает ошибку вместо подмены другой.
3. Скачивает архив встроенным торрент-клиентом, проверяя части по хешам. При повторном запуске проверяет имеющиеся части и продолжает загрузку. По завершении торрент-сессия останавливается.
4. Проверяет пути и структуру архива, доступное место, распаковывает его во временную папку и проверяет CRC. Пароли, ссылки, пути за пределы папки распаковки и неоднозначные имена не поддерживаются.
5. Находит папку с `dlc_*.scs`, включая архивы с внешней папкой. Устанавливает карты в корень выбранной игры и файлы из `bin/win_x64` / `bin/win_x86` в соответствующие подпапки. Проверяет соответствие имени архива выбранной игре, сохраняет исполняемый файл игры. Документация остаётся в архиве. Неизвестная структура вызывает понятную ошибку до замены файлов.
6. Сохраняет оригиналы заменяемых файлов в `.ets-launcher/backups/<номер>/original` внутри игры, затем заменяет файлы. При отмене или ошибке восстанавливает оригиналы и удаляет добавленные файлы. Журнал позволяет восстановить незавершённую установку при следующем нажатии **Установить DLC** после аварийного выхода.

Кнопка **Остановить** отменяет текущую операцию. При обычном закрытии окна приложение сначала завершает остановку и откат, затем закрывается. Готовый архив остаётся в кэше.

В свёрнутых **Настройках** можно выбрать папку текущей игры вручную, повторить поиск и изменить корень кэша загрузок. Папки ETS2 и ATS запоминаются отдельно. Существующий кэш ETS2 остаётся в `Загрузки/ETS Launcher`, ATS использует подпапку `ATS`. Старые настройки ETS2 загружаются без повторного выбора папки. Настройки хранятся в AppData. Резервные копии сохраняются в папке соответствующей игры после успешной установки.

Для VPN с обходом по приложениям добавьте именно `dist/ets-launcher.exe` в исключения. Настройки VPN приложение не меняет. Доступность загрузки зависит от сайта и наличия пиров. Совместимость содержимого DLC с версией игры определяется выбранным источником.

## Сборка

Проект проверен с Rust 1.99.1 (Windows GNU). Локальный toolchain находится в `.tools`, системный PATH не меняется.

```powershell
# Если локальный Rust ещё не установлен
.\scripts\bootstrap.ps1

.\scripts\cargo.ps1 test --locked
.\scripts\cargo.ps1 build --release --locked
.\scripts\package.ps1
```

`package.ps1` собирает `dist`: лаунчер, требуемые GNU DLL, папку `tools/7zip` с официальными `7z.exe`, `7z.dll` и лицензиями. Переносить нужно всю папку `dist`. Источник и контрольные суммы 7-Zip приведены в `assets/7zip/ORIGIN.md`.

Для системного GNU нужны инструменты MinGW/LLVM, для MSVC — соответствующие Build Tools. Обёртка `scripts/cargo.ps1` настраивает локальные LLVM dlltool и LLD.

## Автосборка GitHub Actions

Workflow **Windows build** запускается при push, pull request и вручную через **Actions → Windows build → Run workflow**. Он проверяет форматирование, Clippy и тесты, собирает Windows x64 на Rust 1.99.1 (MSVC), затем проверяет установку из готового `.exe` на временных папках ETS2 и ATS.

Готовое приложение: **[Releases](https://github.com/frd21313123123/ets-launcher/releases) → самая новая сборка → ets-launcher-windows-x64.zip**. Скачайте ZIP, распакуйте целиком и запустите `ets-launcher.exe`. В комплект входят `tools/7zip`, лицензии и `SHA256SUMS.txt`. Рядом с ZIP опубликован его SHA256.

Каждый push в `main` и ручной запуск для `main` публикует проверенную сборку как предварительный релиз `build-<commit>`. Повторный запуск того же коммита обновляет только его файлы. Ветки и pull request проходят проверки без публикации. Выдача ZIP через Releases не использует квоту Actions Artifacts. CI работает с тестовыми архивами и не скачивает настоящий пакет DLC.

Для аналогичной сборки из Windows с настроенным MSVC Rust:

```powershell
$env:RUSTFLAGS = '-C target-feature=+crt-static'
.\scripts\package.ps1 -Target x86_64-pc-windows-msvc
.\scripts\smoke-test.ps1
```

## Проверки

Автоматические тесты работают с временной папкой игры и маленькими архивами:

- HTTP: совпадение байтов, сохранность существующих файлов, обрыв ответа, HTTP 404 и отмена.
- PlayGround: основной файл, актуальные идентификаторы, серверное ожидание и `lock_hash`, проверка `.torrent`.
- BitTorrent: реальная локальная передача, проверка частей, отмена без пиров; цепочка **торрент → архив → распаковка → установка в тестовую ETS2**.
- Установка: RAR5, внешняя папка и кириллица, резервные копии, сохранность исполняемого файла игры, откат при отмене/ошибке, восстановление после прерванного процесса, блокировка параллельной установки, опасные пути и повреждённый архив.
- Поиск игры: дополнительные библиотеки Steam, старый VDF, кириллица, недоступные диски и устаревшие записи.
- ATS: отдельный манифест Steam, защита от выбора папки ETS2, сохранение обеих папок, выбор stable/beta и соответствующие запросы API, установка с сохранением `amtrucks.exe`.
- Динамический каталог: изменение версий и ID без изменения кода, числовое сравнение версий, beta-подпись без beta в имени, появление/исчезновение веток, перенаправление на новый адрес, раздельный кэш и редактирование ссылок.

Полный пакет DLC и запуск настоящей игры в автоматические тесты не входят.

Диагностика получения только `.torrent` из готового приложения с учётом исключения VPN:

```powershell
Start-Process .\dist\ets-launcher.exe -ArgumentList '--fetch-torrent','artifacts/site-smoke' -WindowStyle Hidden -Wait
Get-Content .\artifacts\site-smoke\result.txt
```

Диагностика установки локального архива требует явного пути к тестовой игре и файлу отчёта:

```text
ets-launcher.exe --install-archive <archive> <game-directory> <report-file>
```

Необязательный последний аргумент выбирает игру (`ets2` по умолчанию):

```text
ets-launcher.exe --install-archive <archive> <game-directory> <report-file> ats
ets-launcher.exe --detect-game <report-file> ats
ets-launcher.exe --fetch-torrent <output-directory> ats stable
ets-launcher.exe --fetch-torrent <output-directory> ats beta
ets-launcher.exe --catalog <json-report-file> ats
ets-launcher.exe --catalog <json-report-file> ets2
```
